# 業務担当者の回答集

第5章の演習で、業務担当者の役を代わりに務める資料です。
AI-DLCが業務判断を質問したら、開発者がこの資料で該当する質問を探し、AI-DLCの質問ファイルの`[Answer]:`欄に回答と理由を書いてから作業を再開します。
AI-DLCの質問がここにある項目をすべて尋ねるとは限りません。
記入を終えたら、該当する節の項目がどの欄に入ったかを確かめ、漏れた項目は関連する質問の欄に書き添えます。

この資料は、作業用リポジトリへコピーしないでください。
リポジトリに置くと、Claude Codeが質問する前に回答を読み、業務担当者へ確認する工程が演習から消えます。

ここにあるのは、教材の架空の通販サイトで採用する回答です。
実際の業務担当者に確認した結果ではありません。
自分の業務システムでは、同じ質問を業務担当者へ持っていきます。
ここにない質問が出た場合は、回答を自分で決め、決めた人と理由を要件や設計の記録に残してください。

## 既存機能について（第5章5.4）

| # | 質問 | 回答 |

| G1 | 商品照会は販売終了の商品も返し、商品検索は販売中の商品だけを返す。この差は意図したものか | 意図したものです。過去の受注の明細から販売終了の商品を開けるように、照会は販売状態で絞りません。今回は変えません |

| G5 | 受注取消で、在庫の解除が成功した後に受注側の更新が失敗すると、両者が食い違う。復旧の手順はあるか | 今は運用担当が受注番号で両方を照合して直しています。今回の変更では自動の復旧を作りません |

## ORD-020 受注取消への取消期限の追加（第5章5.4、5.5）

| # | 質問 | 回答 |
| --- | --- | --- |
| D1 | 取消期限は何日か | 受注日から7日です。受注日の7日後の日まで取り消せます。たとえば受注日が9月1日なら、9月8日まで取り消せて、9月9日からは取り消せません |
| D2 | 期限は何を起点に数えるか。受注日か、登録した日時か | 受注日（`ORDER_DATE`）です。利用者に示している日付が受注日のためです |
| D3 | 「今日」はどの時刻帯の日付で判定するか | 日本時間の日付です。サーバーやコンテナの時刻帯の設定によって結果が変わらないようにしてください |
| D4 | 期限を過ぎていたら、どのエラーを返すか | 409で、新しいメッセージID E0113を使ってください。文言は「取消期限を過ぎています。（受注番号：{0}、取消期限：{1}）」で、取消期限は`2026-09-08`の形にします |
| D5 | 受注がない、取消済である、期限を過ぎている、が重なったらどれを返すか | 受注がなければE0111、状態で取り消せなければE0112を、今のまま先に返します。どちらにも当たらない受注だけ期限を確かめます |
| D6 | 受付（`10`）と引当済（`20`）で期限を変えるか | 今回は変えません。どちらも7日です |
| D7 | 期限を過ぎた受注を、運用担当が取り消す手段は要るか | 今回は作りません。範囲外として記録してください |
| D8 | 期限を過ぎていたら、在庫サービスの引当解除を呼ぶか | 呼びません。期限は在庫の解除より前に確かめ、期限を過ぎた受注では在庫も受注も変えないでください |
| D9 | 受注日が未来の受注は取り消せるか | 取り消せます。期限内として扱ってください |
| D10 | 初期データの受注（9月の受注日）は期限を過ぎるが、それでよいか | かまいません。期限は既存の受注にも当てはめます。動作の確認では、確認用の受注の受注日をDBで書き換えて、期限の前後を作ってください |
| D11 | 期限は暦日で数えるか、営業日で数えるか | 暦日で数えます。土日や祝日も1日として数えます |
| D12 | 7日という日数を、コードを変えずに設定で変えられるようにするか | 今回はしません。日数を変えるときは、コードを直してテストし直します |
| D13 | 取消期限を受注照会の応答にも出すか | 今回は出しません。受注照会の応答は今のままにして、取消の拒否だけを作ってください |
